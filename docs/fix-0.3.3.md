# 0.3.3 — исправления после полной ревизии

## P1: `prepare()` больше не убивает свой работающий сервер

До исправления `prepare()` вызывал `initialise()`, а тот — `cleanupStale()`.
Если сервер уже работал и PID-файл существовал, нажатие «Подготовить»
воспринимало собственный сервер как устаревший и убивало его.

Исправлено:

- `prepare()` только проверяет конфигурацию и ставит `standby`;
- `initialise()` не запускает повторную очистку, если сервер уже работает
  или очистка уже выполнялась.

Проверка: сервер запущен, вызван `prepare()`, порт остался открыт,
состояние `ready`.

## P1: проверка владельца порта

`cleanupStale()` теперь использует не только путь исполняемого файла,
но и `portPid` из `Get-NetTCPConnection`.

- путь не совпал — чужой процесс не трогаем;
- порт принадлежит другому PID — процесс не трогаем;
- путь совпал, порт закрыт — это зависший наш сервер, его можно завершать.

- После тестов порты закрыты.

# Ревизия 0.3.2

Проверен коммит `692d317`. Установленные пакетные файлы совпали с репозиторием.

## Оставшаяся проблема

**P1: совпадение пути executable не доказывает принадлежность PID плагину.**
PID-файл содержит только число. Если после сбоя этот PID получил другой
экземпляр того же `flm.exe` или `audiocpp_server.exe`, `cleanupStale()`
сочтёт путь правильным и завершит его. `processIdentity()` получает
`portPid`, но `cleanupStale()` это значение не использует; время создания
процесса и аргументы запуска в PID-файле также не фиксируются.

Проверено изолированной имитацией: PID 12345 имеет ожидаемый путь, но порт
занят PID 54321. Код всё равно направляет `taskkill` в 12345. Ни один реальный
процесс в этом тесте не останавливался. Это важно и для закрытого порта:
просто требовать совпадения владельца порта недостаточно, поскольку зависший
сервер может перестать слушать; для него нужна проверяемая запись личности
процесса, например PID вместе со временем создания и идентификатором запуска.

В отчёте исправления описан тест на `flm.exe` с другим портом 52627. Он
подтверждает, что совпадение пути позволяет завершить процесс, даже когда он
не слушает целевой порт; само по себе это не доказывает его чужую владельцу
принадлежность в конкретном тесте.

## Проверено

- Если путь процесса отличается от ожидаемого, новый код не вызывает
  `taskkill`; при невозможности прочитать путь сохраняет PID-файл.
- Для совпадающего пути очистка больше не зависит от открытого порта. Однако
  без подтверждения конкретного экземпляра она может затронуть другой процесс.
- Живой тест настоящих провайдеров на отдельных случайных портах: Whisper NPU
  6.27 с, Orukeet Vulkan 5.27 с на тестовую фразу, включая запуск и остановку.
  Оба вернули текст, созданные PID завершились, тестовые порты закрылись.
- `node --check` прошёл. Существующие серверы и профиль DSH тестом не закрывались.
- Проверка нулевого `MainWindowHandle` и параметров `windowsHide` сама по себе
  не заменяет визуальное наблюдение окон консольного хоста; отдельной проверки
  окна в живом интерфейсе DSH в этой ревизии не проводилось.

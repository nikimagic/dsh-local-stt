# 0.3.2 — восстановление после аварии

Исправлены две проблемы из ревизии 0.3.1.

## P1: проверка владельца PID

Перед `taskkill` плагин теперь запрашивает у Windows `ExecutablePath`
процесса из PID-файла и сравнивает его с путём собственного сервера.

- путь совпал — процесс останавливается;
- путь другой — это чужой процесс, `taskkill` не вызывается, PID-файл
  удаляется;
- путь получить не удалось — процесс не трогается, PID-файл остаётся
  для следующей попытки.

Проверено на mock-процессе `node.exe`: плагин не убил его и удалил
устаревший PID-файл.

## P2: живой сервер с закрытым портом

Если PID жив, а целевой порт не отвечает, но путь процесса совпадает с
нашим сервером, плагин всё равно завершает процесс через `taskkill /T /F`
и ждёт его исчезновения.

Проверено на реальном `flm.exe`, запущенном на постороннем порту `52627`:
процесс был остановлен, PID-файл удалён.

## Проверки

- `node --check` — успешно.
- Whisper NPU: полный цикл запуск → распознавание → остановка — 5,89 с.
- После тестов порты `52626`, `8028`, `52627` закрыты.
- Окно консоли: `windowsHide: true`, `detached` отсутствует.

Публикация не выполнялась.

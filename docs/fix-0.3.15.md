# 0.3.15 — данные вне пакета

Движки и модели больше не лежат внутри установленного плагина.

## Почему

Установка пакета в pnpm пересоздаёт каталог целиком: сравнения версий нет,
`0.3.13 → 0.3.14` стирало 1,74 ГБ движков при каждом обновлении. Теперь пакет
весит 60 КБ, а данные живут отдельно.

## Где

```text
C:\Users\<user>\.dsh\dsh-local-stt\engines\
```

Порядок выбора каталога: `engines.dir` из конфига → `DSH_LOCAL_STT_ENGINES` →
`<DSH_HOME>\dsh-local-stt\engines`. `DSH_HOME` по умолчанию `~/.dsh`.

## Перенос

Старая раскладка внутри `node_modules\dsh-local-stt\engines` переносится при
запуске автоматически: переименованием на том же диске, без копирования.
Раскладку репозитория (запуск из исходников) не трогаем. Если каталог данных
уже занят, ничего не перезаписывается.

**Ограничение:** перенос срабатывает, только пока старый каталог пакета
существует. Установка через pnpm заменяет каталог целиком, поэтому при
обновлении `0.3.14 → 0.3.15` движки и модели могут скачаться заново. Начиная
с 0.3.15 данные лежат вне пакета, и последующие обновления их не затрагивают.

## Что это даёт

- Обновление плагина — секунда, без затрагивания 1,7 ГБ.
- Профиль и хранилище pnpm не раздуваются.
- Данные переживают переустановку и откат версии.
- Удаление плагина данные не стирает; каталог удаляется вручную.

## Тесты

приоритет конфига и переменной, перенос из пакета, отказ для каталога
репозитория и занятого каталога данных.

# 0.3.12 — кнопка «Проверить обновления» и проверка по хешам

## Что появилось

- Клиентская половина плагина: в карточке плагина (**Плагины → dsh-local-stt**,
  слот `plugins.bundle.config`) появляется кнопка «Проверить обновления».
- Нажатие запускает у обоих провайдеров полную проверку: размер и SHA-256
  каждого файла движка и модели. Это же делает штатная кнопка «Скачать и
  подготовить» в карточке голосового ввода.
- Найденное повреждение удаляется и скачивается заново.
- Для движка при распаковке записывается манифест `.installed.json` с хешами
  файлов; раскладка без манифеста один раз принимается и запоминается.

## Как это работает

```text
нажатие          → checking   (пересчёт хешей; ~2 с на 650 МБ)
всё сошлось      → standby    «Проверка пройдена»
файла нет/битый  → downloading (архив движка) → loading → downloading (модель)
ошибка           → failed с причиной и ресурсом
```

Кнопка в панели ввода подписана состоянием: «проверка файлов»,
«скачивание …%», «распаковка движка», «Проверка пройдена».

## Цена проверки

Полный пересчёт читает 1,6 ГБ с диска: на этой машине 2,1 с для Whisper и
2,3 с для Orukeet. На медленном HDD будет дольше — это осознанный выбор в
пользу честной проверки целостности.

## Проверки

```text
node --check index.js client.js lib/engines.js lib/models.js
node test/zip.test.mjs
node test/engines.test.mjs
node test/models.test.mjs
```

2,1 и 2,3 с, состояние «движок ок, модели: нет 0, повреждено 0». Все состояния
подготовки проверены схемой клиента DSH 0.2.2-rc.3.

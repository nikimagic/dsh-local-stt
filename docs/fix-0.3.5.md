# 0.3.5 — отмена старта, логи и защита от второго DSH

## P1: `cancel()` прерывает `startServer()`

Добавлен отдельный `AbortController` для запуска сервера. `cancel()`
прерывает цикл ожидания порта, а не только убивает уже найденный процесс.

Проверка: отмена через 200 мс после старта завершила ожидание примерно за
1 секунду, порт остался закрыт.

## P2: два DSH с одним профилем

В PID-файле теперь есть `ownerPid` — PID процесса DSH, который запустил
сервер. Если PID-файл принадлежит другому живому DSH:

- сервер отвечает — второй экземпляр использует его как внешний;
- сервер не отвечает — новый сервер не запускается, выставляется
  `cleanupBlocked`.

## P2: неизвестный старый PID больше не теряется

Если `cleanupStale()` не может проверить владельца PID, запуск нового
сервера блокируется. PID-файл не перезаписывается, старый процесс не
теряется.

## P2: логи FLM

stdout/stderr `flm.exe` теперь пишутся в `flm/app/plugin.log`. Логи
audio.cpp — в `tts_cpp/logs/audio-vulkan/plugin-stdout.log`.

## P2: внешний baseUrl

По умолчанию разрешён только loopback. Внешний адрес требует явного
`allowRemote: true`.

## Проверки

- `node --check` — успешно.
- Нормальное распознавание Whisper — успешно, порт закрыт.
- `cancel()` во время старта — отмена примерно за 1 с.
- Внешний `baseUrl` без `allowRemote` — отклонён.
- PID-файл с живым `ownerPid` другого экземпляра — запуск заблокирован.

Публикация не выполнялась.
